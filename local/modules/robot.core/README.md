Модуль - Сайт для проведения соревнований по робототехнике (robot.core)
===

## Разработчик:
Студент-магистр поволжского государственного технологического университета, выпуск 2025 года

Ссылка на репозиторий, в котором производилась разработка - https://github.com/ArtyomKorn1lov/RoboticsCompetition

Ссылка на репозиторий с последней версией модуля - https://github.com/ArtyomKorn1lov/robot.core

## Краткое описание:
Модуль представляет собой решение на любой платформе БУС. Решение предназначено для разворота сайта для проведения соревнований по робототехнике или иным соревнованиям, проводимым в школах или университетах. Задача web-сайта - информирование о проводимом событии его участников, а так же регистрация участников на данное событие.

## Требования к развороту решения:
- **apache** `>=2.4`
- **php** `>=8.1`
- **Редакция 1С-Битрикс** - любая редакция, включая редакцию "Старт"
- **Версия ядра 1С-Битрикс** `>=23` (*рекомендуется*, возможна работа и на более старых версиях ядра)
- **Количество сайтов под решение** - 2 шт
- **Сторонние модули**:
  - **Миграции для разработчиков** `>=5.0.2` - [ссылка на модуль](https://marketplace.1c-bitrix.ru/solutions/sprint.migration/)
  - **Информационные блоки, инструменты** `>=4.9.5` - [ссылка на модуль](https://marketplace.1c-bitrix.ru/solutions/asd.iblock/)

## Инструкция по развороту проекта:
- Подготовить CMS 1С-Битрикс к установке модуля:
  - Установить сторонние модули, указанные в требованиях выше
  - Создать 2 сайта (список сайтов в административном разделе CMS) или выделить существующие, для последующего использования для данного решения
  - Подготовить корневую директорию для будущего сайта (в папке не должно быть файлов и папок кроме папок `/bitrix`, `/local`, `/upload` или симлинки на них, `.htaccess`, `robot.txt` и других служебных файлов, не относящихся к 1С-Битрикс)
  - Сервер настроить на использование `/bitrix/routing_index.php` вместо `/bitrix/urlrewrite.php`
- Поместите данный модуль `robot.core` в папку `/bitrix/modules/` или в `/local/modules/`
- Проверьте `.env`-файл, чтобы все параметры соответствовали `.env.example`, если файла нет, создайте его и скопируйте содержимое `.env.example` в него
- Перейдите в административную часть сайта по пути `Marketplace -> Установленные решения`
- В списке решений найдите решение **"Сайт для проведения соревнований по робототехнике"** и установите модуль
- Проследуйте инструкции установщика и выполните все необходимые шаги
- После установки модуля сайт будет готов к эксплуатации и наполнению контента

### Пример настройки на использование `/bitrix/routing_index.php` вместо `/bitrix/urlrewrite.php`:
Если для вашего сайта используется `.htaccess`, то найдите в данном файле следующий код:
```
RewriteCond %{REQUEST_FILENAME} !/bitrix/urlrewrite.php$
RewriteRule ^(.*)$ /bitrix/urlrewrite.php [L]
```
Замените его на данный код:
```
RewriteCond %{REQUEST_FILENAME} !/bitrix/routing_index.php$
RewriteRule ^(.*)$ /bitrix/routing_index.php [L]
```

## Краткая информация про административный раздел:
- Редактирование контента:
  - Тип инфоблока "Соревнования - контент" - путь в админке `Контент -> Соревнования - контент`
  - Тип инфоблока "Соревнования - обратная связь" - путь в админке `Контент -> Соревнования - обратная связь`
  - Справочник "Страны" - путь в админке `Контент -> Highload-блоки -> Страны`
  - Справочник "Страны англ. версия" - путь в админке `Контент -> Highload-блоки -> Страны - англ. версия`
  - Справочник "Типы полей для формы" - путь в админке `Контент -> Highload-блоки -> Типы полей для формы`
  - Справочник "Поля формы регистрации" - путь в админке `Контент -> Highload-блоки -> Поля формы регистрации`
- Настройки сайта - путь в админке `Настройки -> Сайт робототехники`
- Настройки модуля - путь в админке `Настройки -> Настройки продукта -> Настройки модулей -> Сайт для проведения соревнований по робототехнике`
- Доступен визуальный редактор для блоков, отображаемых в публичной части сайта

### **Логирование**:
- Логи записываются в папку `/logs`, представляют собой файлы вида `"Текущая дата".log`
- Логируются только php-ошибки кастомного функционала модуля

### **Кэширование**:
- При установке модуля предлагается выбрать время жизни кэш-файлов (если время не выбрано, то по умолчанию время жизни будет 3600000 секунд или ~1 месяц) для кастомного функционала, поставляемого из модуля, а именно: *события соревнования, мероприятия событий, программа проведения мероприятий, регистрация на событие, контактная информация в шапке и футере сайта и на странице "контакты"*
- При редактировании контента в административной части сайта, для отображения выше перечисленного функционала происходит автоматический сброс кэша
- Чтобы вручную сбросить, кэш нужно прейти в `Настройки -> Настройки продукта -> Автокеширование -> Очистка файлов кеша` и выполнить очистку кэша

## Для разработчиков:

### Структурные элементы проекта:
- Модуль robot.core - основной backend для сайта, кастомная логика реализована в данном модуле, структура папки `/lib`:
  - `/Base` - абстрактные классы
  - `/Cache` - сервис кэширования
  - `/Controllers` - контроллеры
  - `/DTO` - data transfer objects
  - `/Entity` - сущности, реализующие бизнес-логику
  - `/Enums` - Перечисления
  - `/Exceptions` - кастомные exception'ы
  - `/Logger` - логер
  - `/Middleware` - встраиваемые методы контроллеров
  - `/Repositories` - репозитории
  - `/Services` - сервисы, use-cas'ы
  - `/Tools` - вспомогательные helper'ы
  - `/Views` - представления для вывода данных при загрузке страниц
  - `Constants.php` - общие константы проекта
- Кастомные компоненты:
  - `robot:multiple.include.area` - компонент включаемая область с множественным кол-вом подключаемых файлов, с возможностью их редактирования
  - `robot:template.component` - компонент-шаблон для вывода логики из модуля
- Frontend на vue 3 - расположен в `/(local|bitrix)/js/robot/`
- Шаблон сайта - `robot`, структура:
  - `/app` - Сборка стилей, простых js-скриптов, статических изображений, иконок, шрифтов и тд
  - `/components` - шаблоны компонентов для текущего сайта
  - другие элементы шаблона сайта

### Модуль robot.core:
- Автозагрузка классов происходит через `composer` из папки `/lib`, для проекта используется ООП, рекомендуется вести разработку в этом стиле, в рамках структуры описанной выше
- Инициализация контроллера, инициализация переменных окружения и создание namespace контроллеров происходит в файле `include.php`
- В `.settings.php` - регистрация namespace контроллеров в системе и регистрация классов для сервис-локатора
- Для миграции данных используется модуль `sprint.migration`, для данного модуля используются отдельные миграции, которые можно создать в админке по пути `Настройки -> Миграции для разработчиков -> Миграции для сайта робототехники (robot_core)`
- Таблица `robot_core_settings`, которая используется для хранения данных настроек сайта, создаётся и заполняется при установке модуля, для неё миграций не создавалось
